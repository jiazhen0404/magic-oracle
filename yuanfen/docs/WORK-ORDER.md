## 零、先讀這三件事

**1. 不要手改 `index.html` 的 `<script>` 開頭那段。**
從 `<script>` 到 `/* ───── 介面 ───── */` 註解之間是 `npm run build` 自動產生的，會被覆蓋。要改引擎或文案就改 `src/`，改完跑 build。介面註解**以下**的 UI 程式碼是手寫的，可直接改。

**2. 改文案之後必跑 `npm run lint`。**
339 個 open×core×close 組合、六條語意規則。全過才能 commit。規則說明在 `docs/COPY-SPEC.md`。

**3. 分數計算永遠不送出生日。**
引擎是純函數，全在瀏覽器端跑。頁面上寫著「兩組生日不會被儲存，也不會離開你的裝置」。**任何一次把生日 POST 出去，這句話就得拿掉**——接金流時特別注意，訂單只帶分數與品項，不帶生日。

## 常見的坑（都踩過）

**bundle 名稱衝突**：所有模組會被併到同一個作用域，新模組的函式名要確認全域唯一。曾經 `self-values.js` 的 `pick` 撞到 `copy.js` 的 `pick`，瀏覽器直接 SyntaxError 整支掛掉——**node 端測不出來，只有跑瀏覽器才會爆**。

**`build.js` 的 require 正則**：支援 `const { a } = require()` 與 `const A = require()` 兩種。加新的引用寫法要確認會被剝掉，否則 `require` 帶進瀏覽器就爆。

**運算子優先序**：`(seed ^ x) >>> 0 % arr.length` 是錯的，`%` 綁得比 `>>>` 緊。要拆成兩行。

**免費層的分數不能受時辰影響**：`draw()` 裡刻意算兩次——免費那次不傳 `hour`，另一次傳。合併成一次的話，填了時辰的人會發現分數突然不一樣。

**文案的語意重複**：`lint.js` 的 6-gram 只能抓字面，抓不到換句話說。`CONCEPTS` 概念群才是抓「同義重述」的關鍵，補新文案時如果出現新概念要加進去。**而且規則檢查不能取代人眼——補完一定要抽三到五組完整輸出讀過。**
