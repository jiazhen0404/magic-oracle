## 這是什麼

輸入兩個人的生日（可選時辰），用四柱干支算出「緣分指數」與三個維度，免費看到完整診斷，付費 NT$199 讀 20 段報告。

**產品限定曖昧期**——不是交往中、不是分手後。所有文案都以「還沒有答案的那一段」為前提。

| | 有時辰 | 無時辰 |
|---|---|---|
| 段數 | 20 | 19 |
| 字數 | 2,532 | 2,265 |

---

## 三條不能破的規則

**1. 不要手改 `index.html` 的 `<script>` 開頭那段。**
從 `<script>` 到 `/* ───── 介面 ───── */` 之間是 `npm run build` 產生的，會被覆蓋。改引擎或文案就改 `src/`。介面註解**以下**的 UI 程式碼才是手寫的。

**2. 改文案必跑 `npm run lint`。**
1,284 個組合、六條語意規則，全過才能 commit。規則說明在 `docs/COPY-SPEC.md`。

**3. 生日永遠不離開瀏覽器。**
引擎是純函數。頁面上寫著「兩組生日不會被儲存，也不會離開你的裝置」——這是唯一無法被競品複製的差異。**接金流時訂單只帶分數與品項，不帶生日。**

## 架構：文字從哪裡來

四個軸各自獨立，這是這套系統的核心設計。理解這個才知道要改哪裡。

| 軸 | 檔案 | 決定什麼 | 分類數 |
|---|---|---|---|
| **格局** | `src/shape.js` | 順不順、對不對等 → 前三段敘事 | 10 種 |
| **節奏** | `src/tempo.js` | 怎麼開始的 → 第 02 段 | 7 種 |
| **維度** | `src/copy.js` | 溫度／重量／長度各一段 | 8×5×8 key |
| **風味** | `src/flavour.js` | 綁在命盤上的個人化句 | 日支 12／日干 10／納音 30 |

**格局與節奏是兩件不同的事。** 兩個人可以同樣 70 分、同樣 `onePoint` 格局，但一組是「轟轟烈烈」、一組是「日久深情」。加新內容前先確認要掛在哪個軸上。

### 分數不決定敘事

前三段不由分數排名決定，由 `shape.js` 判讀盤面配置。原因：實測有 10.9% 的情況「最低維度」與次低只差 0–2 分，這時候斷言「真正卡住你們的是溫度」是硬掰。

**差距不足 8 分時不指名短板**，改成誠實說「盤上沒有明顯的短板」（34.5% 的組合走這條）。這條邏輯不要改回分數排名。

## 待辦（依建議順序）

### 1. Worker 路由　🔴 阻擋所有測試

主站是 Cloudflare Workers（`src/oracle.js`）。若 `wrangler.jsonc` 的 routes 是 `unfinished.tw/*`，會攔截 `/yuanfen/`。

在 Worker 最前面加：

```js
const url = new URL(request.url);
if (url.pathname.startsWith('/yuanfen')) return env.ASSETS.fetch(request);
```

**驗收**：`unfinished.tw/yuanfen/` 出現曖昧合盤，不是抽籤首頁。

### 2. 金流串接　🔴 最高優先

**現況**：`index.html` 的 `$('u-cta')` click 事件直接把 20 段渲染出來。

**要做的**：

1. 刪掉 `index.html` 裡兩處 `preview-note`（HTML 與 CSS 各一）
2. 按鈕改成導向 ECPay，比照現有 99 元延伸籤流程，金額 199，品項「曖昧合盤 · 完整報告」
3. **付款後要能還原同一份報告**，但不能把生日存進訂單。作法：生日編碼進回跳網址

   ```
   /yuanfen/?paid=<orderNo>&a=19910404&b=19861230&ha=9&hb=21
   ```

**驗收**：未付款不展開；已付款回跳後自動展開且內容與預覽一致；訂單資料搜不到任何生日欄位。

### 4. 性別稱謂

目前稱謂寫死「他」。`report()` 與 `render()` 都已接受 `names` 參數：

```js
report(last.full, { A: '你', B: '他' })
render(r, birth, { A: '你', B: '他' }, scene)
```

加一個下拉「對方是：他／她／對方」，傳進 `names.B`。

**真正的成本不在下拉**：`src/` 底下有些句子直接寫死了「他」而不是 `{B}`（例如 `other-position.js`、`tempo.js`）。要全檔搜尋「他」逐一判斷。

**驗收**：選「她」之後，20 段報告裡沒有任何一個「他」字。

### 5. 立春精確表　✅ 已完成（v1.3）

`src/solar.js` 直接算太陽視黃經（Meeus 低精度，誤差約 ±15 分鐘），解出黃經抵達 315° 的時刻。不是查表，是實算，所以 1900–2100 都涵蓋。

驗證方式：立春逐年漂移應為 +5.81 小時、閏年 −24 小時。1901–2100 共 199 個年際差，**偏差超過 0.6 小時的有 0 年**。

副產品：24 節氣全部算得出來，所以月柱也排了（本版不參與計分，只列在干支表供對照）。

## 常見的坑（都實際踩過）

**bundle 名稱衝突**：所有模組併到同一個作用域，新模組函式名要確認全域唯一。曾經 `self-values.js` 的 `pick` 撞到 `copy.js` 的 `pick`，瀏覽器直接 SyntaxError 整支掛掉——**node 端測不出來，只有跑瀏覽器才會爆**。

**`build.js` 的 require 正則**：支援 `const { a } = require()` 與 `const A = require()` 兩種。新的引用寫法要確認會被剝掉。

**運算子優先序**：`(seed ^ x) >>> 0 % arr.length` 是錯的，`%` 綁得比 `>>>` 緊。拆兩行寫。

**免費層分數不能受時辰影響**：`draw()` 刻意算兩次——免費那次不傳 `hour`。合併成一次的話，填了時辰的人會發現分數突然不一樣。

**語意重複抓不到**：`lint.js` 的 6-gram 只抓字面。`CONCEPTS` 概念群才抓得到「換句話說」，補新文案若出現新概念要加進去。**而且規則檢查不能取代人眼——補完一定要抽三到五組完整輸出讀過。**

**否定句**：lint 的極性判斷要先剝掉「不會／不再／不是／沒有」開頭的子句，否則「不是爭吵，是各過各的」會被判成負面。這個漏洞補過一次。

**檔名關鍵字刪檔**：曾經用 `if 'star' in filename` 刪星星素材，把 `start-*.png` 一起刪了（start 裡含 star）。批次刪檔要用完整比對。
