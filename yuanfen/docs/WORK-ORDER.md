## 開工前必讀

### 1. 不要手改 `index.html` 的 `<script>` 開頭那段

從 `<script>` 到 `/* ───── 介面 ───── */` 是 `npm run build` 產生的，會被覆蓋。改引擎或文案改 `src/`。**介面註解以下**的 UI 程式碼才是手寫的。

### 2. 每次改完跑這兩個

```bash
npm run lint    # 文案 1356 組合（七條語意規則）＋ 全域名稱衝突掃描
npm run build   # 併 bundle 並注回 index.html
```

`npm run lint` 包含 `checkglobals.js`——**所有模組會被併到同一個作用域，頂層識別名必須全域唯一**。已抓到四次真實衝突（`pick`、`HARSH`、`SHENG`／`KE`／`GAN_WUXING`、`LEVELS`），每一次都是瀏覽器直接 SyntaxError 而 **node 端測試全過**。

### 3. 生日永遠不離開瀏覽器

引擎是純函數。頁面上寫著「兩組生日不會被儲存，也不會離開你的裝置」——這是唯一無法被競品複製的差異。**接金流時訂單只帶分數與品項，不帶生日。**

## 架構

### 判讀層（決定「說什麼」）

| 軸 | 檔案 | 決定什麼 |
|---|---|---|
| 格局 | `shape.js` | 順不順、對不對等（10 種） |
| 節奏 | `tempo.js` | 怎麼開始的（8 種） |
| 相遇 | `encounter.js` | 在什麼場合遇上、多久顯現 |
| 主動方 | `initiator.js` | 誰先動心／誰先出手（5×3） |
| 機會 | `chance.js` | 走到一起的機會分級、卡點、翻盤條件 |
| 下一步 | `movefirst.js` | 該由誰先開口、方式、時機 |
| 夫妻宮 | `palace.js` | 各自期待的相處模式（5×5＝25 種） |
| 維度 | `copy.js` | 溫度／重量／長度（9×5×9 key，三截組合） |
| 風味 | `flavour.js` | 綁在命盤上的個人化句 |

### 表現層（決定「怎麼說」）

| 檔案 | 作用 |
|---|---|
| **`wrap.js`** | **段落的開場與收尾（66 句框架）** |
| `takeaway.js` | 每段的「這一段的重點」 |
| `basis.js` | 算式揭露 |

`wrap.js` 是 v2.1 新增的。原本後加的判讀軸只寫了一句話，最差的段落只有 3 種、最常見那句佔 36.8%。套上三截機制之後：

```
種類最少的段落　3 種 → 12 種
最常見那句佔比　43.6% → 15.4%
```

**框架句只框住情境，不碰判斷內容**——因為同一段落的所有 key 共用一組框架，框架句必須對該段的每一種 key 都成立。

## 四條不要改回去的邏輯

**分數不決定敘事。** 前三段由 `shape.js` 判讀盤面配置，不是分數排名。實測 10.9% 的情況「最低維度」與次低只差 0–2 分，那時候斷言「真正卡住你們的是溫度」是硬掰。差距不足 8 分時不指名短板（34.5% 走這條）。

**交叉柱比對不能拿掉。** `yuanfen.js` 的 `crossPairs()` 比對非同位置的柱。只比同柱會漏掉大部分關係——實測某組盤同柱只看到 2 組，交叉有 5 組。

**`chance` 與 `shape` 有一致性約束。** 格局無推力（`quiet`／`blank`／`plain`）或日干比和時，機會不得落在「很有機會」。拿掉會出現「你們沒有特別強的推力」配「條件都在」的自相矛盾。

**各軸只負責自己那一件事。** 分數帶不講「怎麼開始的」，那是節奏軸的地盤。`lint.js` 的 **R7** 就是在擋這件事——曾經分數帶「緣暖」寫了「不是一見面就燒起來」，與節奏軸「一開始就強烈吸引」在同一頁相鄰兩段直接矛盾，發生率 8.8%。

## 常見的坑（都實際踩過）

**只覆蓋 `src/` 不 build**：網頁跑的是 `index.html` 內嵌的 bundle，改動不會生效。**最常發生的一個。**

**bundle 名稱衝突**：踩過四次，每次都是瀏覽器 SyntaxError 而 node 端全過。`npm run lint` 會自動掃描。

**新增分類 key 沒補齊所有表**：加 `po`（六破）時有 16 張分類表需要對應文案，漏掉 `basis.js` 一張就讓整個免費頁掛掉——同樣是 node 端測不出來。

**函式內的 require**：`build.js` 只剝除行首的頂層引用。寫在函式裡會讓 `require` 帶進瀏覽器。

**整段替換 CSS 太危險**：曾用「從 `.upsell{` 到 `.upsell .seal{`」當範圍替換，中間夾著三百多行其他規則全被刪掉。**只針對單一規則做替換。**

**運算子優先序**：`(seed ^ x) >>> 0 % arr.length` 是錯的，`%` 綁得比 `>>>` 緊。

**免費層分數不能受時辰影響**：`draw()` 刻意算兩次——免費那次不傳 `hour`。

**新增框架句要跑互撞檢查**：`wrap.js` 的 66 句框架彼此之間也會重複。曾有兩處（`caution` 與 `values` 都寫「知道它在哪裡」、`attitude` 與 `appearance` 都用「這一段講的是」），同一份報告裡會出現同樣的開場。

**語意重複抓不到**：`lint.js` 的 6-gram 只抓字面，`CONCEPTS` 概念群才抓得到「換句話說」。而 **R7 的字表擋得住字面、擋不住語意**——曾經「有些緣分沒有故事，只有日子」通過所有檢查，但配上「轟轟烈烈：你們是撞上的那一種」時，那明明就是故事。**補完文案一定要把八種節奏並排讀一次。**

## 已知的文案債（不影響功能）

**14.5% 的段落，「這一段的重點」與內文有 8 字以上重複。**

原因是新模組的重點句直接取了段落收尾。已用程式移除內文裡重複的句子（45.6% → 14.5%），剩下的要靠重寫重點句解決，約 30 句。**留給文案流程，不要交給 Code。**

## 下一階段的變體要靠不同方法

現在最少的段落是 12 種，那是「3 個 key × 4 開場 × 4 收尾」的結果。**再加框架句只會線性成長。**

要再上一個量級，得增加**判斷句本身的 key 數**，那就回到引擎：

- 十神細分（現在日干只分五種，加陰陽變十種，正偏之別在曖昧期意義完全不同）
- 六合分六種（午未和合／寅亥義合／辰酉融合／卯戌／巳申刑合／子丑泥合，性質差很多）
- 流年應期（能講出具體年份，是唯一能讓使用者回頭再算的理由）

三項都不需要旺衰判定，可以在師資回覆之前做。詳見 `docs/SOURCES.md`。
