### 1　生日不放在回跳網址上　✅ 已定案

施工單原本寫的是把生日編碼進回跳網址：

```
/yuanfen/?paid=<orderNo>&a=19910404&b=19871230&ha=9&hb=21
```

**不採用。** 那樣寫「不進資料庫」是真的，但生日仍然會外流到：

| 誰會拿到 | 途徑 |
|---|---|
| Google Analytics | GA4 自動送 `page_location`，含完整 query string |
| 綠界 | 回跳時的 Referer |
| 瀏覽器歷史紀錄 | 明文留存 |
| 任何被分享的連結 | 貼給朋友就洩漏兩個人的生日 |

而頁面上寫著「除非你主動送出準確度回饋，否則兩組生日不會離開這一頁」。

**改成：** 生日存 `localStorage`，以訂單編號為 key；回跳網址只帶
`?paid=<orderNo>`。同一個瀏覽器付款、回跳，localStorage 必然還在。
換裝置開回跳連結會還原不了，那時請使用者重新輸入生日即可——
計算是免費的，付費解鎖的是報告本身。

### 2　比照 99 元強制勾選同意條款　✅ 已定案

延伸籤的 `createOrder` 有這段強制檢查，合盤要比照：

```js
// 法規要求：數位內容不適用七日解除權，必須留下「事先同意」的證據
if (consent.terms !== true || consent.digitalContent !== true) {
  return json({ error: 'consent_required' }, 400);
}
```

合盤同樣是在台灣銷售的數位內容，同意時間要存進訂單。

## 已實作、不要改回去的

| 決定 | 原因 |
|---|---|
| 早子／晚子採**子初換日**（23:00 後日柱算次日） | 市面常見排盤的預設是 23 點換日。日柱是本產品最吃重的一根柱（夫妻宮＝日支、溫度＝日支關係、重量＝日干），對不上等於整份判讀對不上 |
| 代名詞在**輸出前統一替換**（`src/fill.js`），不逐一傳 `names` | 模組十幾個，新增一個忘了接就會漏，而漏掉的那句要等使用者選了「她」才看得到 |
| 準確度回饋**只在使用者主動送出時**才上傳生日 | 頁面承諾如此。抽籤本身不呼叫任何 API，這一點有自動測試守著 |
| 付費區用**金框**而不是紅金卷軸 | 卷軸的紅邊與金紋吃掉左右各約 18%，手機行長從 21 字掉到 14 字 |
| 重疊比對的門檻是 **0.12**，不是施工單寫的 0.5 | 實測同主題、獨立撰寫的中文只有 0.16–0.27，0.5 永遠不會觸發，等於沒有守門 |
