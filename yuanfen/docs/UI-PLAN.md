# 緣分指數 · UI 與動畫規劃

## 一、素材配置

現有 78 件素材，依畫面分配。**同一件素材不要在兩個相鄰畫面重複出現**，否則整站會顯得只有一種花樣。

| 畫面 | 主素材 | 輔助 |
|---|---|---|
| 01 輸入資料 | `arch-frame` 拱形花框（包住整個表單） | 背景星點 8–10 顆 |
| 02 免費結果 | `medallion` 圓形徽章（包住分數） | `01_moon-star-rule` 分隔線 |
| 03 付費頁 | `wreath-circle` 圓形花環（包住價格） | `33_books-stack`／`34_crystal-ball`／`35_envelope-wax-seal` 當三個特色 icon |
| 04 報告首頁 | `couple-circle` 情侶插畫 | `03_starburst-pearl` 置頂 |
| 報告內文 | `corner-tl` + `corner-br` 對角落 | `03_thin-crystal-rule` 段落間 |
| 分享卡 | `medallion` | — |
| 載入中 | `04_compass-star-pendant` | — |

角落飾 `corner-tl` / `corner-br` 是一對，**只用在報告內文**，固定在頁面左上與右下、`position: fixed`、`opacity: .35`、`pointer-events: none`。這是最省力又最有效的做法：整份報告不管多長，四周都有裝飾，但完全不影響閱讀。

## 二、檔案大小（必須處理）

原始素材 9.2 MB，手機使用者等不完。轉 WebP 後：

```
couple-circle    900×900    2755 KB →  296 KB
corner-tl        700×674    1362 KB →  134 KB
corner-br        700×674    1368 KB →  124 KB
wreath-circle    900×866    1688 KB →  278 KB
arch-frame       760×1140   2204 KB →  269 KB
──────────────────────────────────────────────
                            9.2 MB  →  1.1 MB
```

**規則：**

- 一律轉 WebP，品質 82，最長邊不超過 900px（`arch-frame` 因為是直式，高度 1140）
- 附 PNG fallback 給舊 Safari（`<picture>` 標籤）
- **只有首屏的素材可以直接載入**（輸入頁的 `arch-frame`），其餘全部 `loading="lazy"`
- 報告的角落飾在使用者付費解鎖之後才載入，不要跟首屏搶頻寬

## 三、動畫規劃

原則：**整站只有一個真正的動畫時刻，就是起盤。** 其餘全部是回應操作的小反饋。散在各處的淡入上浮是最容易讓網站顯得廉價的做法。

### A. 起盤（唯一的主場動畫，約 2.4 秒）

使用者按下「開始測算」之後，**不要立刻顯示結果**。占卜需要一段等待，那個等待本身就是體驗的一部分。

```
0.0s  按鈕按下，表單淡出並略微縮小（scale .98）
0.2s  compass-star-pendant 出現在畫面中央，透明度 0 → 1
0.3s  羅盤外圈開始旋轉（8 秒轉一圈，等速，不加速不減速）
0.3s  背景星點依序亮起（stagger 60ms，共 10 顆）
1.6s  羅盤淡出，同時 medallion 圓形徽章從 scale .92 放大到 1
2.0s  分數數字從 0 跑到目標值（ease-out，700ms）
2.2s  等級名與籤語淡入上浮 12px
2.4s  三個維度的量尺金點從左滑到定位（stagger 100ms）
```

數字跑動那一段是關鍵。它讓分數看起來是「算出來的」而不是「查表查到的」，而且會讓使用者盯著螢幕，那正是我們要的注意力。

### B. 微互動（每個都在 200ms 以內）

| 元素 | 動作 |
|---|---|
| 華麗按鈕 | hover `brightness(1.06)`；active 下移 1px |
| 下拉選單 | 開啟時金色邊框亮起 |
| 算式摺疊 | 高度展開 240ms `ease-out`，`＋` 轉成 `－` |
| 目錄項目 | hover 時左側編號變亮金色 |
| 分享卡 | 生成完成時整張卡 `scale .96 → 1`，160ms |
| 鎖頭 | 解鎖時 `01_lock-heart-cream` 換成 `05_unlock-heart-cream`，中間插一個 300ms 的抖動 |

### C. 明確不做的

- **不做視差捲動。** 深色背景加浮動元素會讓文字難讀，而且這份報告要讀 2400 字。
- **不做每個區塊的淡入上浮。** 那是 AI 生成網站最明顯的特徵。
- **不做背景星星閃爍。** 20 顆星星各自閃爍會讓人眼睛累，而且讀長文時特別煩。要有動靜的話，讓 **1 顆** 星星每 8 秒緩慢呼吸一次就夠。
- **不做報告頁的進場動畫。** 使用者付了錢，要的是內容不是表演。

### D. 無障礙

```css
@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important }
}
```

起盤動畫在此設定下直接跳到結果，但**保留 400ms 的延遲**——完全瞬間出現會讓人以為沒送出。

## 四、報告閱讀介面

設計稿上是分頁式（03/19、上一段／下一段），跟目前一次全展開不同。分頁是對的：

- 19 段一次展開會變成一長條，捲不完
- 分頁讓每一段有獨立的份量
- 「03 / 19」本身就在提醒使用者買到多少東西

### 電腦版

```
┌──────────┬────────────────────────────┐
│ 目錄     │  第一部分  先看你們的關係   │
│ 進度 3/19│                             │
│          │  03                         │
│ Ⅰ 先看…  │  明明有感覺，為什麼就是     │
│  01 …    │  走不近？                   │
│  02 …    │                             │
│ ▸03 …    │  （內文）                   │
│  04 …    │                             │
│ Ⅱ 他與你 │  ┌─ 這一段的重點 ─────┐    │
│ Ⅲ …      │  └────────────────────┘    │
│          │       ‹ 上一段  下一段 ›    │
│ [下載PDF]│                             │
└──────────┴────────────────────────────┘
```

左側目錄 `position: sticky`，捲動時固定。當前段落高亮，已讀過的段落編號變暗金色。

### 手機版

頂部一列：`第一部分 先看你們的關係　03 / 19`
底部固定：`← 上一段　下一段 →`
目錄收在漢堡選單裡。

### 「這一段的重點」

設計稿上每段底部有一個帶鎖頭的摘要框。這是**新內容，19 段要 19 句**，每句約 20 字，是該段的一句話收束。

例：
> 有吸引，不代表靠近的速度一定相同。

這批要另外寫，可以依段落的 key 做成模組（跟其他文案一樣的作法）。

## 五、實作順序

1. **素材轉檔**（WebP + 尺寸壓縮）—— 半天，收益最大
2. **報告閱讀器改成分頁**（含左側目錄、進度、上下段）—— 1–2 天
3. **起盤動畫**（羅盤旋轉 + 數字跑動）—— 1 天
4. **「這一段的重點」19 句** —— 文案工作
5. **角落飾與拱形框套版** —— 半天
6. **微互動** —— 半天

PDF 下載建議先用瀏覽器原生列印（`@media print` 樣式），一天內能做完；真正產生 PDF 要處理中文字型嵌入，成本高很多，等有人真的要求再做。
