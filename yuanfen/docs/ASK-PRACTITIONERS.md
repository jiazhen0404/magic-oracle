# 要問師資的問題

`RULES.md` 規則 11 說：**旺衰與喜用神是八字裡最沒共識、最容易算反的一步。
判反了，「一見鍾情」的判定會整個顛倒——比不夠深還糟。**

這份就是那條規則指向的文件。底下每一題都是**實際會改變輸出**的分岔，
不是學理討論。每題都附上「如果答錯會怎樣」，方便判斷輕重。

**怎麼用這份文件：** 拿給命理師，請他直接在每題底下寫答案。
不需要解釋理由（雖然有更好），只要一個明確的選擇。
答案回來之後，對應的程式常數改掉即可——刻意都寫成具名參數了。

## 一、日主強弱

### Q1　月令的權重

得月令（月支本氣同我或生我）在總判定裡佔多少？

- [ ] 一票否決：失令就是身弱，其他因素只能微調
- [ ] 約一半
- [ ] 約三分之一
- [ ] 其他：＿＿＿＿

**程式對應**：`strength.js` 的 `W_MONTH`
**答錯會怎樣**：春天生的木命幾乎都會被判成身強，夏天生的水命幾乎都身弱——
整批使用者的判讀往同一個方向偏。

### Q2　通根怎麼算分

日干在地支「有根」，三種根的分數比例？

| 根 | 例（日干甲） | 分數 |
|---|---|---|
| 本氣根 | 寅（甲） | ＿＿ |
| 中氣根 | 亥（甲為中氣） | ＿＿ |
| 餘氣根 | 辰（乙為餘氣） | ＿＿ |

- [ ] 只認本氣，中氣餘氣都不算
- [ ] 本氣 3：中氣 2：餘氣 1
- [ ] 其他：＿＿＿＿

**程式對應**：`strength.js` 的 `ROOT_WEIGHT`

### Q3　虛透算不算

天干透出比劫或印星，但地支完全無根（「虛透」），算不算生扶？

- [ ] 完全不算
- [ ] 打折算（幾成：＿＿）
- [ ] 照算

**程式對應**：`strength.js` 的 `EMPTY_GAN_RATIO`

### Q4　分界線畫在哪

總分換算成 0–100，身強身弱的界線？中間要不要留一段「中和」？

- [ ] 50 一刀切，沒有中和區
- [ ] 中和區 45–55
- [ ] 中和區 40–60
- [ ] 其他：＿＿＿＿

**程式對應**：`strength.js` 的 `MID_BAND`
**為什麼重要**：這一題決定「不確定」有多常發生。
本產品的設計是——**落在中和區就不下配偶星的斷言**，寧可少說也不說反。
中和區訂得越窄，講得越多，但講錯的機率也越高。

## 二、從格（最危險的一題）

### Q5　要不要做從格

日主極弱時，傳統上可能轉「從格」，而從格的喜忌與正格**完全相反**。

- [ ] **不做**。一律按正格判，極弱就是身弱
- [ ] 要做，門檻是總分低於＿＿
- [ ] 要做，但只做從財／從殺，不做從兒從勢

**答錯會怎樣**：這是全部十一題裡最嚴重的一題。
判錯不是「不夠準」，是**整份判讀的喜忌全部相反**——
該說「這段緣對你是助力」的，會講成「是耗損」。

**如果師資沒有把握，請選第一項。** 少一層深度，好過整份反過來。

## 三、調候

### Q6　調候優先還是扶抑優先

冬天生的水命（水已經很旺）、夏天生的火命，
要優先取調候用神（冬取火、夏取水），還是照扶抑法？

- [ ] 一律扶抑，不做調候
- [ ] 調候優先
- [ ] 只在嚴重失衡時（如亥子丑月的水、巳午未月的火）才調候

**程式對應**：`strength.js` 的 `TIAOHOU_MODE`

## 四、配偶星

### Q7　誰才算配偶星

- 男命：
  - [ ] 只有正財是妻，偏財不算
  - [ ] 正財偏財都算
- 女命：
  - [ ] 只有正官是夫，七殺不算
  - [ ] 正官七殺都算

**程式對應**：`spouse.js` 的 `SPOUSE_STAR_SCOPE`
**產品考量**：本產品的情境是**曖昧**，不是婚配。
若嚴格取正財／正官，很多使用者會落入「命中無配偶星」（見 Q9）。

### Q8　配偶星「好不好」怎麼判

兩個判準會衝突，以哪個為準？

| 判準 | 說法 |
|---|---|
| 喜忌 | 配偶星是喜用神＝好 |
| 力量 | 配偶星有根、透干、不受剋＝好 |

- [ ] 以喜忌為準
- [ ] 以力量為準
- [ ] 兩者都要，衝突時＿＿＿＿優先

**衝突的實例**：身強的男命，財星為喜用（好），但財星無根被劫財剋（沒力）。
這時要說「你的正緣是助力」還是「你的正緣不容易握住」？

### Q9　命中沒有配偶星怎麼辦

男命四柱無財、女命四柱無官殺，怎麼判？

- [ ] 以夫妻宮（日支）代之
- [ ] 看大運流年有沒有引動（**本產品不排大運，等於不做**）
- [ ] 直接說「這一層看不出來」，不硬掰

**程式對應**：`spouse.js` 的 `NO_STAR_FALLBACK`
**發生率**：待實測。程式寫好後會掃十萬組樣本統計，數字太高就要重新考慮 Q7。

### Q10　同性組合怎麼取配偶星　★ 這題傳統上沒有答案

本產品明確支援男男、女女。傳統「男以財為妻、女以官殺為夫」建立在異性配偶的前提上。

- [ ] **各自按自己的性別取**（男看財、女看官殺），組合不影響
- [ ] 按關係中的角色取，由使用者自己選
- [ ] 同性組合不做配偶星這一軸，只做現有的夫妻宮

**這題如果師資答不出來，是正常的**——傳統文獻裡沒有這個情境。
那就變成產品決策，由負責人拍板。

**產品傾向**：第一項。理由是它不要求使用者自我歸類成「比較男方的那個」，
那種問法本身就會冒犯人。且配偶星在本產品裡講的是
「你期待什麼樣的人」，本來就是從自己的命盤看出去的。

## 五、資料不全

### Q11　沒有時辰還能不能判旺衰

本產品的出生時辰是選填，實際上有相當比例的使用者不填。
缺時柱（四柱少一根）時：

- [ ] 照判，誤差可接受
- [ ] 照判，但要在文字上降低斷言強度
- [ ] 不判，配偶星這一軸整段不出現

**程式對應**：`spouse.js` 的 `REQUIRE_HOUR`
**現況**：引擎已有 `hasHour` 旗標，三種做法都接得上。
